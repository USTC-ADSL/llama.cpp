## 目标

补一组第二台设备上的最小 decode baseline，用于后续和主设备做 cross-device 对照。

本轮只尝试：

- `CPU` 单线程 decode
- `GPUOpenCL` decode
- `qnn-npu` decode

统一设置：

- 工具：`llama-bench`
- 模型：`qwen2_0.5b`
- `-p 0 -n 128 -c 2048 -b 1 -ub 1`
- `-ctk f16 -ctv f16`
- `-t 1`
- `--no-warmup`

## 亮屏状态

这部分目前还不能作为严格的“亮屏基线”使用。

原因：

- 直接记录的 `dumpsys power` 日志里，before/after 都仍然是 `mWakefulness=Asleep`
- 我尝试过：
  - `svc power stayon true`
  - `am start -a android.settings.SETTINGS`
- 单独执行唤醒命令后，设备短暂返回过 `mWakefulness=Awake`
- 但把 baseline 命令串起来后，记录下来的 power state 仍然回到了 `Asleep`

因此，本文件中的结果应视为：

- **第二台设备的 preliminary baseline**
- **不是严格满足亮屏条件的正式基线**

## 失败项说明

### 1. `qnn-npu` static baseline 失败

报错核心信息：

`pre-allocated tensor (cache_k_upd-0) in a buffer (qnn-npu) that cannot run the operation (SET_ROWS)`

这说明当前 tree 下，静态单后端 `qnn-npu` decode 并没有和本轮主线验证的 AoT shared-host 三段切分一起打通。它是另一条独立问题，后续需要单独修。

### 2. CPU 路径结束时 abort

CPU baseline 虽然打印出了结果表：

- `tg128 = 14.79 tok/s`

但进程在退出阶段仍然 `Aborted`。这意味着这条数据可以暂时作为“观测值”保留，但不应直接拿去做正式论文图表。

## 当前可用的最小结论

在 `fd8657d6` 上，当前至少已经拿到一条可工作的 preliminary GPU decode baseline：

- `GPUOpenCL tg128 = 74.33 tok/s`

这条数据可用于后续判断第二台设备和主设备在 GPU decode 上的量级差异。

但如果要把第二台设备纳入正式对照实验，仍然需要先解决两个问题：

1. 亮屏状态需要能稳定保持并且可被日志确认。
2. CPU abort 与 `qnn-npu` static baseline abort 需要进一步定位。
