# 任务 007：补齐 `fd8657d6` 上 `Qwen2/Qwen3` 的非功耗 baseline

日期：2026-03-22

> 补充说明：本记录中的 `qnn-npu` 数据是第二设备上的 **static non-AoT baseline**。后续对 `Qwen2` 的 full-graph AoT 复核见 `progress/2026-03-22-008-fd8657d6-qnn-aot-config-verification.md`。

## 背景与目标

用户要求开始在另一台设备 `fdxxx` 上做实验，并明确：

- 当前 USB 供电下功耗数据不稳定，暂时不测功耗
- 需要 `Qwen2` 和 `Qwen3` 的数据
- 测试长度需要按模型调整

基于当前主线优先级，这轮实验先收口为：

1. 第二设备上的 `Decode` static baseline
2. 第二设备上的 `Prefill` static baseline

模型选为：

- `Qwen2-0.5B`
- `Qwen3-1.7B-Q8_0`

## 关键证据

### 1. `Decode` 上两类模型的静态最强后端都是 `GPUOpenCL`

`Qwen2-0.5B`：

- CPU：`14.74 / 14.76`
- GPUOpenCL：`74.32 / 74.70`
- qnn-npu：`10.87 / 10.92`

`Qwen3-1.7B-Q8_0`：

- CPU：`16.02 / 15.84`
- GPUOpenCL：`27.11 / 27.17`
- qnn-npu：`10.12 / 10.07`

### 2. `Prefill` 上两类模型的 static non-AoT 最强后端也都是 `GPUOpenCL`

`Qwen2-0.5B`：

- CPU：`325.29 / 329.79 / 267.00`
- GPUOpenCL：`1360.94 / 1773.88 / 1343.09`
- qnn-npu：`323.28 / 325.31 / 260.76`

`Qwen3-1.7B-Q8_0`：

- CPU：`86.75 / 89.07 / 65.95`
- GPUOpenCL：`383.59 / 530.85 / 582.85`
- qnn-npu：`75.28 / 66.02 / 65.93`

### 3. `Qwen3 qnn-npu prefill` 暴露出明显状态敏感性

正式批量记录里：

- `pp64 = 75.28`

但之前 smoke run 里：

- `pp64 = 89.55`

这说明第二设备上至少当前仍存在：

- 热状态影响
- 运行顺序影响
- 亮屏控制不稳

因此不能把这轮 `r=1` 结果当成强方差结论。

## 当前结论

这轮第二设备 baseline 实验完成后，可以更有把握地说：

1. `fd8657d6` 上 `Qwen2/Qwen3` 的 `Decode/Prefill` static baseline 都已可测。
2. 两个模型、两个 phase 的 static baseline 最强后端都仍然是 `GPUOpenCL`。
3. 这里的 `qnn-npu` 数字是 static non-AoT 结果，不能与 full-graph AoT 吞吐混为一谈。
4. `qnn-npu` 在这台设备上没有表现出 static non-AoT 统治力：
   - `Qwen2` 上常常只是贴近 CPU
   - `Qwen3` 上在 `Prefill` 里甚至低于 CPU
5. 因此第二设备数据进一步支持当前主线：
   - 研究重点应放在阶段异构性、operating points 与 runtime overhead
   - 而不是假设静态 NPU 必然最优
